- The mfd/ai-filemetadata integration supports `^1.6` again, now including 1.7.1 and later ([#96](https://github.com/netresearch/t3x-nr-llm-compat/issues/96)). On 1.7.1 and later the bridge takes the new `EventDispatcher` constructor argument into account, dispatches `ModifyRequestDataEvent` with the same request data as the original, and passes listener changes to the prompt, temperature, `max_tokens`/`max_completion_tokens` and image detail level on to nr-llm. A listener change nr-llm cannot express (for example added tools or another model) makes the bridge refuse the request with `UnmappableRequestChangeException` and log a warning naming the changed keys; the request is never sent to OpenAI instead. An empty answer raises an `UnexpectedValueException` from 1.7.1 on, as in the original, so no empty alt text is stored; up to 1.7.0 the bridge keeps returning it.
