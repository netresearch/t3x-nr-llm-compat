- The mfd/ai-filemetadata integration supports `^1.6` again, now including 1.7.1 and later ([#96](https://github.com/netresearch/t3x-nr-llm-compat/issues/96)). On 1.7.1 and later the bridge takes the new `EventDispatcher` constructor argument into account, dispatches `ModifyRequestDataEvent` with the same request data as the original, and passes listener changes to the prompt and the image detail level on to nr-llm. Any other listener change (for example added tools, another model, a changed temperature or a token limit) makes the bridge refuse the request with `UnmappableRequestChangeException` and log a warning naming the changed keys; the request is never sent to OpenAI instead. Temperature and token limits are refused because nr-llm's vision providers do not send a temperature ([netresearch/t3x-nr-llm#1474](https://github.com/netresearch/t3x-nr-llm/issues/1474)) and nr-llm reports no finish reason to detect a truncated answer ([netresearch/t3x-nr-llm#1473](https://github.com/netresearch/t3x-nr-llm/issues/1473)). From 1.7.1 on an empty image or an empty answer raises an `UnexpectedValueException`, so no empty alt text is stored; up to 1.7.0 the bridge keeps returning an empty string. A CI cell runs the unit and functional tests against 1.7.0.
