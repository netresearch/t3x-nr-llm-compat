- mfd/ai-filemetadata 1.7.1 and later with a `ModifyRequestDataEvent` listener: while the AI File Metadata integration is active, a listener that changes anything but the system prompt (for example adds a web-search tool) makes the bridge refuse every request, so no alt texts are generated. An upload logs the refusal as a warning. `ai:generate-alt-texts` stops at the first file. The backend's alt-text suggestion button reports a failed request, because `AiGeneratedAltTextAjaxController::suggestAction()` catches no exception. An empty answer also stops `ai:generate-alt-texts` at that file and fails the suggestion request, as the original 1.7.1 does; an empty (0-byte) image does not, it is marked done with an empty alt text. `nrllm:compat:status` names the registered listeners, also before the integration is enabled. Remove or adapt such a listener, or leave the integration disabled ([#96](https://github.com/netresearch/t3x-nr-llm-compat/issues/96)).
